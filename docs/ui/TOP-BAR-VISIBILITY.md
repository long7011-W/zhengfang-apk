# 顶栏文字随玻璃透明度消失

## 已定位的原因

`SystemTopBar` 在启用 Backdrop 的设备、预设壁纸、展开状态下将玻璃层透明度设为 `collapse = 0`。
`192b69a` 增加了这段 `graphicsLayer`，但玻璃修饰符仍挂在包住标题、副标题、返回和操作按钮的父 `Box` 上，导致整棵前景子树透明。滚动时 `collapse` 增大，文字才出现。副标题又有自己的收拢动画，两个透明度相乘会进一步降低可见度。

这是可由布局结构和数值直接解释的问题；不需要假设字体加载失败、GPU 缓存或手动滚动才能触发重绘。此前针对入场动画状态的修复没有覆盖这里。

## 修复约束

- 玻璃背景使用独立、无内容的 `matchParentSize` 子节点，标题行是它的兄弟节点。
- 背景的透明度、模糊与染色只影响背景；前景保留原有尺寸、间距、颜色、字号变化和点击区域。
- 副标题保留折叠时收拢的设计，主标题和操作按钮不随玻璃显现进度淡出。
- 不关玻璃、不降低采样质量或刷新率，不使用定时刷新或模拟滚动。

## 同类路径排查

| 路径 | 检查结论 |
| --- | --- |
| 设置、抢课工作台 | 同一 `SystemTopBar` 父层透明度问题。 |
| 问卷中心/详情、添加/编辑课程、课表设置、教务能力提示 | 同一公共顶栏；统一修复同时生效。 |
| `GlassPageScaffold`、`SystemFormPage` | 继承该顶栏。覆盖插件中心/工具/服务、教务与问卷网页、Cookie 网页、学校适配/历史、反馈历史和表单页。 |
| 课表 `ScheduleHeader` | 玻璃层和文字/操作列是兄弟节点；背景透明度不包住文字。 |
| 成绩 `MeasuredGradesHeader` | 背景与前景布局分开；大小标题的显隐由折叠布局有意控制，操作栏独立。 |
| 课程详情 `CourseDetailContent` | `scheduleDetailGlass` 是内容列的背景兄弟节点；标题的图层只做入场位移。 |
| 对话框、子页、任务操作菜单 | 遮罩与内容分层；内容透明度属于页面/菜单自身的入退场进度，打开后归一。 |
| 底栏、分段栏 | 透明/不直接绘制的文字节点是单独的折射采样副本；正常前景不继承这些节点的透明度。 |
| 通用内容卡片、任务卡片、顶部按钮 | 背景色 alpha 只影响色值，或仅对明确隐藏的按钮使用 presence；没有复用顶栏的玻璃 alpha 父容器。 |

排查依据包括全 UI 的 `graphicsLayer`、`alpha`、`drawContent` 和透明采样节点搜索，以及上述共同容器的调用结构。没有将所有有意的淡入淡出改为不透明。

## 回归与验收边界

`SystemTopBarVisibilityTest` 在 Robolectric API 32 的 native canvas 上绘制实际 Compose View，检查标题区域的深色像素，不仅检查语义树中是否存在文字。覆盖未滚动时的标题/副标题/返回/操作按钮、折叠与反向恢复、切页后重建、玻璃开关与自定义底色切回预设，并检查按钮点击。

JVM 绘制回归用于证明这处父层透明度问题。API 32 真实 GPU、系统字体、壁纸与实际设备动画仍须实机验收；本工作区不运行设备或模拟器测试。
