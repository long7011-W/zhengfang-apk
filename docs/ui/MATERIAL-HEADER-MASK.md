# 非玻璃顶栏遮罩修复（1.0.96 开发分支）

## 反馈及定位

用户提供的课表截图显示：关闭液态玻璃后，顶栏出现宽灰色圆角框，中间是清晰的矩形缺口。为处理这条反馈，测试构建的 CI 请求保持暂停。

检查发现课表非玻璃分支使用独立的硬件 elevation 阴影，填充色则另外按滚动进度降低透明度；两者没有一起退场，填充还使用了与按钮不同的 MaterialTheme 底色。该组合存在留下阴影框的风险，与截图现象吻合，但本地未复现反馈设备的硬件渲染结果，不能把特定 GPU 根因当成已证实。

同时确认：成绩顶栏在 backdrop 为空时完全没有普通底色回退；两个共用背景组件只凭传入的 backdrop 绘制玻璃，没有自行检查用户实时关闭玻璃的状态。

## 修改

- 课表和成绩通过相同背景组件绘制非玻璃底色：一次填满整个圆角区域，使用当前外观的 solidSurface，填充本身随原有进度显隐。去掉课表非玻璃分支的硬件阴影，不使用挖空、背景采样或离屏遮罩。
- 状态栏在非玻璃模式使用普通底色渐变，保留原有细下缘渐隐。玻璃关闭或者没有采样源时均可回退。
- 两个页面同时检查实时玻璃设置，不因保留了非空 backdrop 而继续创建捕获层、组合采样及透镜锚点。
- 背景仍是文字和按钮的兄弟节点；圆角、布局、点击区域、课表显隐进度和成绩延迟显隐保持原值。开启玻璃时的模糊、折射、光泽、内阴影和质量参数没有调整。
- 检查 SystemTopBar：已使用普通背景回退且前景独立，无本次硬件阴影组合；继续运行其设置、抢课等标题绘制回归。

## 验证方法

`MaterialHeaderSurfaceTest` 使用 Robolectric API 32 native canvas 绘制真实 Compose 节点，对圆角内两侧及中央同时采样，检查浅色/深色、轻微滚动、半展开、全展开、反向恢复和玻璃开关切换。检查圆角外及边界外不残留阴影，并验证课表视图切换和成绩刷新操作。

旧实现下 5 项新增测试均因底色像素不匹配而失败：状态栏回退、成绩无底色、课表底色不一致、已有 backdrop 时关闭玻璃、共享圆角背景的非玻璃绘制。它们证明回退绘制不符合预期，**不等同于在 JVM 中重现了截图里的 OEM 矩形灰框**。

最终定向回归 **11/11 通过，0 失败、0 跳过**：新增底色/开关/交互检查 5 项，SystemTopBar 文字与点击检查 4 项，成绩操作区避让 1 项，课程详情短宽窗/大字体布局 1 项。课表日期额外检查实际文字像素，不仅依赖可访问性节点“存在”。

过程记录：第一轮修复后 10/11 通过，剩余项是测试用“日”匹配到了日视图与星期日两个节点；改为明确的“日视图”描述并增加日期像素检查后，最终 11/11 通过。未为测试放宽产品绘制要求。

可复核证据：工作区 `evidence/vps-material-header-before`（5 项旧实现失败）、`evidence/vps-material-header-after`（首轮 10/11）、`evidence/vps-material-header-final`（最终 11/11），各含 XML、stdout/stderr、退出状态与计数。使用 `scripts/vps-gradle.sh`、单 worker、1 GiB Gradle 堆和现有小测试进程；没有设备/模拟器或完整 APK 打包。

## 发布及设备边界

本次只修改 App。插件、SDK、网站及授权策略不变。未构建 APK，未触发 CI/CD、同步 Gitee、创建标签、更新 main 或发布公告。

待用户测试同一设备：关闭液态玻璃，课表轻滑/完全上滑/回到顶部，切换深浅色和玻璃开关，再检查成绩顶栏；确认完整圆角底色、无矩形缺口和灰框，标题与操作始终可见。API 32/OEM GPU 及真实设备验收仍未完成。
